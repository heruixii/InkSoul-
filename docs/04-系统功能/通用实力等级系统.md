# 通用实力等级系统

## 概述

通用实力等级系统是一个灵活的框架，用于根据不同小说的设定自动适配主角的实力限制。系统会根据小说类型、主角当前境界自动生成相应的实力规则，确保AI生成的内容符合原著设定。

## 功能特点

- **自动适配**：根据不同小说的设定自动调整实力系统
- **多类型支持**：支持修炼、等级、战力等不同类型的实力系统
- **动态生成**：根据主角当前境界实时生成实力限制规则
- **可配置**：为每个小说单独配置实力等级和规则
- **默认配置**：为新小说提供默认实力系统（修炼型、通用型）
- **自动识别**：自动识别小说原著主角、世界观、禁止概念、细化规则
- **智能推荐**：基于术语关系分析智能推荐替代术语
- **多类型术语库**：支持仙侠、玄幻、奇幻、都市等多种小说类型的术语库
- **虚构地名识别**：支持识别小说中的虚构地名（如北原、中州、天庭等）
- **地理距离计算**：基于地名特征和频率自动计算地区间距离
- **角色关系网络分析**：分析角色间的关系类型和强度
- **时间线一致性检查**：检测时间矛盾和不合理的时间安排
- **物品/资源追踪**：追踪物品的获取、使用、失去及使用方法和效果
- **势力/组织识别**：识别小说中的势力/组织及其关系
- **实力成长轨迹分析**：分析实力提升的合理性，检测不合理跳跃
- **地理连续性验证**：验证角色移动的地理合理性
- **因果关系分析**：分析事件间的因果关系，检测逻辑漏洞
- **角色性格特征提取**：提取角色性格特征，确保行为一致性
- **设定冲突检测**：检测不同设定之间的冲突
- **术语使用一致性**：确保术语使用的一致性

## 系统架构

### 1. 实力系统配置 (`data/novels/_metadata.json`)

每个小说可以在元数据中配置自己的实力系统：

```json
{
  "novel_id": {
    "powerSystem": {
      "type": "cultivation",
      "name": "蛊师境界",
      "levels": [
        {"name": "一转初阶", "power": 1, "description": "只能对付普通野生蛊虫"},
        {"name": "一转中阶", "power": 2, "description": "可击败普通一转蛊师"}
      ],
      "rules": [
        "主角只能击败实力相近或略低的敌人",
        "禁止让主角做出超出其境界能力的壮举"
      ]
    }
  }
}
```

- **加载配置**：从小说元数据读取实力系统配置

- **多类型支持**：支持不同类型的实力系统
- **默认配置**：为新小说提供默认配置
- **自动识别原著主角**：从小说数据中自动识别原著主角
- **自动识别世界观**：从小说数据中自动识别地区、距离规则、合理性规则
- **自动识别禁止概念**：从小说数据中自动识别禁止使用的术语
- **自动识别细化规则**：从小说数据中自动识别细节规则
- **术语关系分析**：分析术语共现关系，提升规则生成准确性
- **智能替代术语推荐**：基于相似度和上下文推荐替代术语
- **多类型术语库**：支持仙侠、玄幻、奇幻、都市等术语库
- **虚构地名识别**：支持识别小说中的虚构地名
- **地理距离计算**：基于地名特征和频率计算地区间距离

- **物品/资源追踪**：追踪物品的获取、使用、失去及使用方法和效果
- **势力/组织识别**：识别小说中的势力/组织及其关系
- **实力成长轨迹分析**：分析实力提升的合理性，检测不合理跳跃

### 3. AI提示词集成

在AI生成时自动插入实力限制：

```
【主角实力限制】主角当前境界为一转初阶，必须严格遵循该境界的实力范围：
- 当前实力描述：只能对付普通野生蛊虫，无法与二转以上蛊师正面对抗

- 无法击败的境界：三转初阶、四转初阶、...
```

## 配置指南

### 为新小说添加实力系统

#### 方式一：使用默认配置

系统会自动为新小说提供默认配置：
- **修炼型**：适用于仙侠、武侠类小说
- **通用型**：适用于玄幻、奇幻类小说

#### 方式二：自定义配置

在 `data/novels/_metadata.json` 中为小说添加 `powerSystem` 配置：

```json
{
  "your_novel_id": {
    "powerSystem": {
      "type": "custom",
      "name": "你的实力系统名称",
      "levels": [
        {"name": "等级1", "power": 1, "description": "描述"},
        {"name": "等级2", "power": 2, "description": "描述"}
      ],
      "rules": [
        "规则1",
        "规则2"
      ]
    }
  }
}
```

### 配置参数说明

- `type`: 实力系统类型（cultivation、generic、custom）
- `name`: 实力系统名称（如"蛊师境界"、"修仙境界"）
- `levels`: 实力等级列表
  - `name`: 等级名称
  - `power`: 实力数值（用于比较）
  - `description`: 该等级的能力描述
- `rules`: 通用规则列表

## 实力限制规则

系统会自动根据主角当前境界生成以下限制：

### 可击败的境界
- 实力相近或略低的敌人（差距不超过2级）

### 无法击败的境界
- 实力高2级以上的敌人

### 通用规则
- 主角只能击败实力相近或略低的敌人
- 禁止让主角做出超出其境界能力的壮举
- 主角拥有的资源数量和品质必须符合其境界
- 战斗必须考虑实力差距，主角应避免与远超自己的敌人正面冲突
- 实力提升需要合理的剧情铺垫

## 维护说明

### 添加新小说

1. 在 `data/novels/_metadata.json` 中添加小说元数据
2. 配置 `powerSystem` 字段（可选）
3. 如果不配置，系统会使用默认配置

### 修改现有配置

1. 编辑 `data/novels/_metadata.json`
2. 修改对应小说的 `powerSystem` 配置
3. 重启后端服务器使配置生效

### 测试配置

1. 创建新故事，选择该小说
2. 查看AI生成的事件是否符合实力限制
3. 如有问题，调整配置后重启服务器

1. **重启服务器**：修改配置后需要重启后端服务器才能生效
2. **境界匹配**：确保主角档案中的 `startingRealm` 与配置中的等级名称匹配
3. **数值合理**：`power` 数值应该合理反映实力差距
4. **规则清晰**：规则描述应该清晰明确，便于AI理解和遵守

## 自动识别功能

### 原著主角自动识别

系统可以自动从小说数据中识别原著主角：

- **识别方式**：统计角色在事件和角色数据中的出现频率
- **识别数量**：自动识别前3名高频角色作为原著主角
- **配置位置**：自动更新到 `data/novels/_metadata.json` 的 `canonProtagonist` 字段
- **支持多主角**：支持识别多个原著主角（数组形式）

### 世界观自动识别

系统可以自动从小说数据中识别世界观设定：

- **地区识别**：通过地名模式匹配识别小说中的地区
  - 支持虚构地名（如北原、中州、天庭）
  - 不依赖现实世界地名库
  - 通过上下文模式识别（如"前往XX"、"抵达XX"）
- **距离规则**：基于地名特征和频率自动计算地区间距离
  - 方向词分析（东vs西=极远）
  - 地理特征分析（海vs漠=远）
  - 频率分析（频率相近=距离近）
  - 置信度评分
- **合理性规则**：生成通用的世界观合理性规则

### 禁止概念自动识别

系统可以自动识别小说中不应该使用的术语：

- **小说类型识别**：自动识别小说类型（仙侠、玄幻、奇幻、都市）
- **术语库匹配**：根据小说类型使用相应的术语库
- **智能替代推荐**：
  - 基于术语相似度推荐
  - 基于上下文分析推荐
  - 基于术语库推荐
- **多类型术语库**：
  - 仙侠术语库（16个术语）
  - 玄幻术语库（7个术语）
  - 奇幻术语库（5个术语）
  - 都市术语库（3个术语）

### 细化规则自动识别

系统可以自动从小说数据中识别细节规则：

- **术语关系分析**：分析术语共现关系
- **分类生成**：
  - 存储相关（如蛊虫存储）
  - 战斗相关
  - 修炼相关
  - 使用相关
- **相关术语**：在规则中包含经常共现的术语信息

## 真实性增强功能

系统实现了10个逻辑功能来提升小说的真实性和减少错误率：

### 角色关系网络分析

分析角色之间的关系，确保角色互动符合关系设定：

- **关系识别**：识别师徒、敌对、盟友、亲属、上下级等关系类型
- **关系强度量化**：根据互动频率和内容判断关系强度
- **关系一致性检查**：确保角色互动符合已建立的关系设定
- **矛盾检测**：检测角色关系矛盾（如敌对角色突然合作）
- **提示词生成**：生成角色关系网络提示词供AI参考

### 时间线一致性检查

检测时间矛盾和不合理的时间安排：

- **事件时间识别**：从文本中提取时间信息（年、月、日、季节等）
- **时间线构建**：建立事件的时间序列
- **时间矛盾检测**：检测角色同时在多个地方、时间倒流等矛盾
- **时间合理性验证**：确保事件时间间隔合理
- **提示词生成**：生成时间线一致性要求提示词

### 物品/资源追踪

追踪物品的获取、使用、失去，确保物品逻辑合理：

- **重要物品识别**：识别关键物品（蛊虫、法宝、武器、丹药等）
- **物品流向追踪**：记录物品的获取、使用、丢失历史
- **使用方法追踪**：记录物品的使用方法（如攻击、防御、治疗）
- **效果逻辑追踪**：记录物品使用后的效果（如造成伤害、恢复生命）
- **资源合理性检查**：确保物品不会凭空出现或消失
- **数量验证**：检测物品数量矛盾（如重复获得）
- **提示词生成**：生成物品使用方法和效果提示词

### 势力/组织识别

识别小说中的势力/组织及其关系：

- **势力识别**：识别小说中的势力/组织（宗、门、派、阁、楼等）
- **势力关系分析**：分析势力之间的敌对、盟友、从属、竞争关系
- **势力行为规范**：确保势力行为符合设定
- **势力冲突检测**：检测势力行为矛盾
- **提示词生成**：生成势力信息和关系提示词

### 实力成长轨迹分析

分析实力提升的合理性，防止不合理跳跃：

- **实力变化追踪**：记录主角实力变化节点
- **成长节奏分析**：分析实力提升的合理性
- **跳跃检测**：检测不合理的实力跳跃（跨越超过2级）
- **成长路径验证**：确保成长路径符合设定
- **提示词生成**：生成实力成长轨迹提示词

### 地理连续性验证

验证角色移动的地理合理性：

- **移动轨迹追踪**：记录角色移动轨迹
- **距离合理性检查**：确保移动符合世界观距离规则
- **跳跃检测**：检测不合理的位置跳跃（短时间内跨越极远距离）
- **时间-距离匹配**：确保移动时间与距离匹配
- **提示词生成**：生成地理连续性要求提示词

### 因果关系分析

分析事件间的因果关系，检测逻辑漏洞：

- **因果关系识别**：识别事件之间的因果链
- **因果链提取**：提取包含原因和结果的事件
- **逻辑漏洞检测**：检测只有结果没有原因的事件
- **分支处理**：处理多分支剧情的因果关系
- **提示词生成**：生成因果关系提示词

### 角色性格特征提取

提取角色性格特征，确保行为一致性：

- **性格分析**：通过行为描述分析角色性格（勇敢、谨慎、狡猾、正直等）
- **性格一致性**：确保角色行为符合性格设定
- **性格矛盾检测**：检测角色性格突变
- **行为预测**：基于性格预测角色行为
- **提示词生成**：生成角色性格提示词

### 设定冲突检测

检测不同设定之间的冲突：

- **设定提取**：提取小说的各种设定
- **冲突识别**：识别不同设定之间的冲突
- **冲突解决**：提供冲突解决方案
- **一致性验证**：确保世界观一致性
- **检测示例**：禁止概念与细化规则冲突检测

### 术语使用一致性

确保术语使用的一致性：

- **术语使用追踪**：记录术语使用情况和上下文
- **一致性检查**：确保术语使用一致
- **混用检测**：检测术语混用
- **使用规范**：建立术语使用规范

用户可以创建自定义术语库：

- **文件格式**：JSON格式
- **命名规则**：`{libraryName}.json`

#### 自定义术语库示例

```json
{
  "name": "自定义术语库名称",
  "type": "custom",
  "commonTerms": [
    {
      "term": "禁止的术语",
      "reason": "禁止原因",
      "alternative": "替代术语1、替代术语2"
    }
  ]
}
```

系统提供了完整的术语库管理API：

- `GET /api/term-libraries` - 获取术语库列表
- `GET /api/term-libraries/:libraryName` - 获取特定术语库

- `DELETE /api/term-libraries/:libraryName` - 删除术语库

获取指定小说的完整元数据配置，包括世界观、禁止概念、细化规则等。

### 更新小说元数据
```
PUT /api/novels/:novelId/metadata
```
更新小说的元数据配置，自动重新加载服务以应用更改。

### 重新识别配置
```
POST /api/novels/:novelId/redetect
```

- `all` - 重新识别所有配置
