# 整体工作流程

## 完整工作流程概览

```
准备阶段 → 数据提取 → 数据验证 → 数据同步 → 验证完成
```

## 详细步骤

### 第一步：准备阶段

#### 1.1 检查环境

```bash
# 检查 Node.js 版本
node --version  # 应为 v14 或更高

# 检查小说文件
ls -lh "Gu Zhen Ren - Gu Zhen Ren.txt"  # 应为 ~14MB
```

#### 1.2 设置 API Key

```bash
# Windows
set DEEPSEEK_API_KEY=sk-你的密钥

# Linux/Mac
export DEEPSEEK_API_KEY=sk-你的密钥
```

#### 1.3 备份现有数据

```bash
# 备份角色卡
cp -r characters characters.backup

# 备份数据文件（如果存在）
cp -r data data.backup
```

#### 1.4 创建必要目录

```bash
# 确保 data 目录存在
mkdir -p data

# 确保 logs 目录存在
mkdir -p logs
```

### 第二步：数据提取

#### 2.1 运行提取脚本

```bash
npm run enrich-story-full
```

**说明**：
- 处理全部 2,698 个章节
- 使用 DeepSeek API 进行智能提取
- **增量提取模式**：已提取章节只提取世界书，未提取章节完整提取
- 支持断点续传
- 每 100 章自动保存进度

#### 2.2 监控进度

```bash
# 查看实时日志（如果后台运行）
tail -f extraction.log

# 或查看进度文件
cat data/extraction_progress.json
```

#### 2.3 预期耗时

- **总章节数**: 2,698
- **API 调用次数**: 约 2,698
- **预计耗时**: 1-2 小时
- **请求间隔**: 0.8 秒

#### 2.4 中断处理

如果脚本中断，重新运行即可自动恢复：

```bash
npm run enrich-story-full
```

脚本会从上次保存的位置继续。

#### 2.5 完成检查

提取完成后，检查输出文件：

```bash
ls -lh data/
```

应包含：
- story_framework.json
- timeline.json
- canon_anchors.json
- character_attributes_cache.json

### 第三步：数据验证

#### 3.1 运行验证脚本

```bash
npm run verify-story
```

#### 3.2 查看验证结果

验证脚本会输出：
- 角色验证准确率
- 事件验证准确率
- 锚点验证准确率
- 错误报告

#### 3.3 审核错误报告

```bash
# 查看纠错建议
cat data/correction_suggestions.json
```

#### 3.4 决定后续操作

根据验证结果：

**准确率 > 80%**: 继续同步
**准确率 60-80%**: 手动审核错误报告，决定是否需要重新提取
**准确率 < 60%**: 考虑重新提取数据

#### 3.5 重新提取（可选）

如果准确率过低：

```bash
# 清空进度
rm data/extraction_progress.json

# 重新提取
npm run enrich-story-full
```

### 第四步：数据同步

#### 4.1 预览同步（推荐）

```bash
npm run sync-characters:dry
```

#### 4.2 审核变更报告

预览模式会显示：
- 将要更新的角色卡
- 每个角色的具体变更
- 跳过的角色及原因

#### 4.3 执行同步

确认无误后执行实际同步：

```bash
npm run sync-characters
```

#### 4.4 查看同步日志

```bash
cat logs/character-sync.log
```

#### 4.5 验证同步结果

```bash
# 检查角色卡是否更新
ls -lh characters/

# 随机抽查几个角色卡
cat characters/角色卡_方源.json
```

### 第五步：验证完成

#### 5.1 运行最终验证

```bash
npm run verify-story
```

#### 5.2 检查故事引擎

1. 启动故事引擎（如果未运行）
2. 测试角色卡显示
3. 验证剧情生成

#### 5.3 清理临时文件

```bash
# 删除进度文件（如果存在）
rm data/extraction_progress.json

# 可选：删除纠错建议文件
rm data/correction_suggestions.json
```

## 快速参考

npm run verify-story

## 时间估算

| 步骤 | 操作 | 预计耗时 |
|------|------|----------|
| 准备阶段 | 检查环境、设置 API Key、备份 | 5-10 分钟 |
| 数据提取 | 运行 enrich-story-full | 1-2 小时 |
| 数据验证 | 运行 verify-story | 1-2 分钟 |
| 数据同步 | 预览 + 执行同步 | 1-2 分钟 |
| 验证完成 | 最终验证、测试 | 5-10 分钟 |
| **总计** | | **1.5-2.5 小时** |

## 注意事项

### 1. 首次运行

- 务必先备份现有数据
- 使用预览模式审核变更
- 分步验证每一步结果

### 2. 重复运行

- 检查是否需要重新提取
- 确认 API Key 有效
- 清理旧的进度文件

### 3. 错误处理

- 查看日志文件定位问题
- 参考故障排查指南
- 必要时联系技术支持

### 4. 数据安全

- 定期备份角色卡
- 使用版本控制系统
- 记录重要变更

## 输出文件清单

### 提取结果
- `data/story_framework.json` - 故事框架
- `data/timeline.json` - 时间轴
- `data/canon_anchors.json` - 原著锚点
- `data/character_attributes_cache.json` - 角色属性缓存

### 验证结果
- `data/correction_suggestions.json` - 纠错建议

### 同步日志
- `logs/character-sync.log` - 同步操作日志

### 临时文件
- `data/extraction_progress.json` - 提取进度（完成后自动删除）

## 下一步

完成整体工作流程后：

1. **测试故事引擎**: 验证角色卡和剧情生成是否正常

3. **定期更新**: 小说更新后重新运行提取流程
